# RepRecorder 详细说明（给使用者）

> 这份说明讲三件事：① 这个软件在你的整合包里会动什么；② 它自己会写哪些文件；
> ③ 它需要你的电脑上有什么。想快速上手，看同目录的《说明-给使用者（简短版）》。

---

## 一、它在你的整合包里会动什么

只有**一个文件**会被改：

| 文件 | 动什么 |
| --- | --- |
| `th123\modules\ReplayDnD\ReplayDnD.ini` | 只改 `MuteMusic` 这一行（点界面上的「录BGM」：开=0 / 关=1） |
| `th123\modules\ReplayDnD-old\ReplayDnD.ini` | 同上 |

就这两行。**整合包里其余的文件，程序一个都不碰。**

下面这些有时候会被误以为"是它改的"，其实都不是：

| 文件 | 其实是谁写的 |
| --- | --- |
| `th123\modules\ScoreTracker\ScoreTracker.ini` | **ScoreTracker 自己**在游戏退出时保存 |
| `th123\config123.dat`、`score123.dat`、`SWRSToys.ini`、`tsk\*`、`modules\SokuLobbiesMod\*`、`modules\giuroll\giuroll.ini`、`modules\WindowResizer\WindowResizer.ini` | 游戏自己玩的时候写的 |
| `replay\**\*.rep` | 你和对手打出来的 replay |
| `replay\**\*.mp4` | 这个软件录出来的成品 |

⚠ `ModLoaderSettings.json` 是**只读**的 —— 程序不会写它。手动去改它有可能和 mod loader 抢文件、导致游戏崩溃。

## 二、它自己会写哪些文件

全部在 `RepRecorder.exe` **旁边**，也就是这个文件夹里：

| 文件 | 是什么 |
| --- | --- |
| `RepRecorder.settings.json` | 你的设置（游戏目录、OBS 路径、ffmpeg 路径、各种开关） |
| `RepRecorder.log` | 运行日志 —— 出问题时报这个文件 |
| `RepRecorder.已静音待恢复` | 程序异常退出时的"声音恢复标记"，正常情况看不到 |

**除了上面 `ReplayDnD.ini` 里那两行，程序不会往整合包里写任何东西。**

## 三、两个最容易踩的坑（本版已自动处理）

1. **OBS 画布尺寸**
   OBS 默认画布是 1920×1080（16:9），而游戏画面是 4:3 —— 不设的话录出来左右会有黑边。
   本版默认就是「自动设置画布」= 开（1440×1080，正好 4:3），不用你管。

2. **`ReplayDnD` mod 没启用**
   没启用的话，游戏不能"带 rep 参数直接播放"，点「开始录制」之后画面会一直停在标题画面。
   点「检查环境」会明确告诉你它是 `已启用 ✓` 还是没启用。

## 四、需要你的电脑上有什么

| 需要 | 必须吗 | 软件怎么找 |
| --- | --- | --- |
| Windows 10/11 + .NET Framework 4.x | 必须 | 系统自带 |
| 【完整包】非想天则整合包 | 必须 | **放哪都可以**。自动找分三步：① 程序附近（程序所在文件夹、它的上一级、以及这两处下面的子文件夹里的 `th123\th123.exe`）② 附近 `SokuLauncher.json` 里写着的游戏位置 —— 整合包被改了名、整个挪到别的盘也认 ③ 前两步都没有就把各个硬盘走一遍（**后台跑，界面不卡**，最多 8 层，几秒） |
| 整合包里的 `ReplayDnD` mod（启用状态） | 必须 | 游戏能"带 rep 直接播放"就靠它，整合包一般默认启用 |
| OBS Studio（28 或更高，自带 obs-websocket 5.x） | 必须 | 自动找：注册表里 OBS 的安装记录 → Program Files 等常见位置 → 每个磁盘根目录下名字带 "obs" 的文件夹 |
| OBS 的 WebSocket 服务器开着 | 自动 | 程序会在 **OBS 没运行时**自动改 `%APPDATA%\obs-studio\plugin_config\obs-websocket\config.json` 把它打开；端口和密码也从这里自动读 |
| `ffmpeg.exe` | **并行录制必须**；单个录制用不到 | 按顺序找：① 程序旁边（含 `bin\`、上一级）② WinGet 装的 ③ `C:\ffmpeg\bin` 这类常见位置、scoop / chocolatey ④ 系统 `PATH` ⑤ 都没有就走一遍硬盘。**第 ⑤ 步找到的会先真跑一次、确认能编视频才用** —— 叫 `ffmpeg.exe` 的文件在别人电脑上很多是别的软件捆的，其中还有音频专用版。也可以在「设置…」里手动指定 |
| 独立显卡 | **不必须** | 并行切分默认用 NVIDIA 的编码器；没有 N 卡会自动改用 CPU 软件编码（慢一些），AMD / 核显机器也能跑 |

### 「检查环境」会把这五项打出来

```
游戏目录：…\th123
OBS     ：…\obs64.exe
WebSocket：127.0.0.1:4455（密码已获取）
ffmpeg  ：…\ffmpeg.exe
ReplayDnD mod：已启用 ✓
```

缺哪一项，那一行会标 ✗ 并直接写出该怎么办：

- 缺 **OBS** → 给一条 winget 安装命令，复制粘贴到 PowerShell 里跑一下就行
- 缺 **ffmpeg** → 告诉你去哪下、下完放到哪；也可以直接在「设置…」里指定它在哪
- 缺 **游戏目录** → 直接带你去「设置…」里指
- **WebSocket** 没启用 → 彻底关掉 OBS（托盘里也要退），再点一次「检查环境」，程序会自己帮你打开

⚠ 上面这些"自动查找"里最慢的一步（走硬盘）是**后台跑的**，所以刚打开软件的那一两秒，
左下角可能还写着「未找到」，过一会儿会自己变成「已就绪」—— 那不是出错，是在找。
「设置…」里的「重新自动检测」和「检查环境」都能让它当场重新找一次。

### 报问题给别人时

窗口标题上写着版本号（例如 `v1.0`），日志第一行也有。把同目录的 `RepRecorder.log`
一起发过去，比口头描述现象有用得多。

## 五、它什么时候会联网

只有两件事：

1. **通过 OBS 的 WebSocket 控制 OBS** —— 连的是 `127.0.0.1`，也就是你自己这台机器，不出网。
2. **启动时查一次有没有新版本** —— 读 Gitee 上的一份小文件（`version.json`），
   6 小时最多查一次。

第二件事：

- **查不到就当没事发生** —— 没网、超时、那份文件被写坏了，都不会弹任何东西，
  只在日志里留一行。绝不会因为"检查更新"把软件卡住或者烦你。
- 查到了会**问你**：告诉你新版本号和更新说明，给你「下载并更新」/「以后再说」/「打开下载页」
  三个出口。**它不会背着你偷偷换掉程序。**
- 「以后再说」会记住那一版，之后不再为它弹。
- 更新包很小（一两百 KB，只含主程序，不含 217MB 的 ffmpeg），下完它会
  把旧的主程序改名成 `.old` 留一手，再放上新的；**中途出任何问题都会还原**，
  不会留下一个坏掉的主程序。下次打开时那个 `.old` 会被自动清掉。
- 换完之后主程序旁边会多一个「无法验证发布者」的确认框（和第一次拿到这个软件时一样）——
  这是因为程序没有买代码签名证书，不是出问题了。

设置文件里只会多记两样东西：上次检查的时间、你点过「以后再说」的版本号。

## 六、一句话

**放到整合包附近最省事（放哪都行，程序会自己找），先启动一次 OBS 再关掉，然后打开软件点「检查环境」—— 就能用了。**
