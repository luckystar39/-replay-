# 48 个老验证脚本：怎么处理（阶段 6.3）

写于 2026-10-03。背景：`RepRecorder\` 下 77 个 `.ps1`，其中 **48 个用原生窗口句柄**找控件
（`FindWindowEx` / `WindowsForms10.*` 类名 / `SendMessage` / `LVM_*`）。
WPF 一个窗口只有一个 HWND、控件没有句柄，所以这 48 个**不是"结果不对"，是根本找不到目标** ——
要么报错退出，要么更糟：`FindWindowEx` 返回 0 之后脚本里没有断言，**静默跑过、什么都没测**。

## 改写过程中抓到的真问题（这才是阶段 6 的价值）

1. **`queueList.SelectionChanged` 根本没接** —— 旧版 `MainForm` 有一句
   「列表里选中几个 rep，「同时录制数量」就跟着变（用户要求）」，移植时漏了。
   WPF 的 `ListBox` 没有原生句柄，没有任何东西提醒你少接了一根线。→ `验证WPF-10` 抓出来，已补。
2. **数量下拉的滚轮守卫漏了** —— 旧版 `cbParallel.MouseWheel` 里把 `Handled` 置 true
   （用户要求"滚轮滚过它不要改它"），WPF 没有。→ 已补 `PreviewMouseWheel`。
3. **`press:`/`set:` 碰勾选框不触发 `Click`** —— 本程序所有勾选框都挂在 `Click` 上
   （保存设置、改 ini），只改 `IsChecked` 的话**值翻了、设置却没落盘**。
   也就是说 `验证WPF-03` 里那些勾选框断言，之前比看上去要弱。→ 已修，现在会补发 `Click`。

## 已知限制（写脚本的人要知道）

- **模态对话框弹着的时候，读取类命令会卡住**：它们走 `Dispatcher.Invoke`，模态框占着 UI 线程。
  一次拖进多个"已经录过"的 rep 就会触发。要先答掉对话框（`验证WPF-11` 是给 `#32770` 发
  `WM_COMMAND/IDNO(7)`，不依赖系统语言）。
- **别让两套脚本同时跑**：每个脚本开头都 `Get-Process RepRecorderWPF | Kill`，
  并行跑会互相杀实例，看起来像功能坏了（这次就踩了）。
- **脚本一律纯 ASCII**：PowerShell 5.1 把无 BOM 的 UTF-8 当 ANSI 读，中文字面量被搅坏之后
  报的错会完全跑偏（这次 `验证WPF-13` 就因为一句中文注释导致断言恒假）。
