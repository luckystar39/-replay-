## 为什么换成了 WPF

旧版拖边框缩放时每步要全量重绘整个控件树（实测约 47ms/步，就是"卡"的来源）。
WPF 版同样场景 6~12ms/步，不需要旧版那套"整窗快照预览"的补丁。界面观感保持不变，
换的是绘制栈。

## 怎么改、怎么编译

1. 用**记事本 / VS Code / Notepad++** 打开要改的 `.cs`（**保存时选 UTF-8**，否则中文会乱码）；
2. **先关掉正在运行的 RepRecorder.exe**，双击 `编译.bat`；
3. 编译成功后双击 `同步到所有文件夹.bat`。

手动编译（`编译.bat` 里就是这一条，**必须带 `/codepage:65001`**，不然中文全乱）：

```
C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe /nologo /target:winexe /codepage:65001 ^
  /out:RepRecorderWPF.exe ^
  /r:"C:\Program Files (x86)\Reference Assemblies\Microsoft\Framework\.NETFramework\v4.7.2\PresentationFramework.dll" ^
  /r:"...\PresentationCore.dll" /r:"...\WindowsBase.dll" /r:"...\System.Xaml.dll" ^
  /r:System.Windows.Forms.dll /r:System.Drawing.dll /r:System.Web.Extensions.dll /r:System.Core.dll ^
  Ui.cs UiShell.cs UiWindow.cs UiDialogs.cs Core.cs Recorder.cs
```

⚠ **编译命令里没有 `/win32manifest`，这是故意的**：DPI 感知在运行时用
`SetProcessDpiAwarenessContext` 打开。写进 manifest 是整个 exe 生效的，
而同一个 exe 里还跑着旧 WinForms 界面 —— 那套是按"DPI 不感知"布局的，
一变感知，在 300% 屏上会缩成原来的 1/3。

## 两个界面怎么切

- **不带参数** → 新 WPF 界面（默认）
- **`--old`**（或 `--winforms`）→ 旧 WinForms 界面
- `--wpf` 仍然认，当同义词忽略（这样桌面上原来那个快捷方式和 `启动WPF.bat` 不会失效）

## 调试接口（改完代码 / 写验收脚本时很有用）

```
RepRecorderWPF.exe --debug-port=7799 [rep 文件或文件夹…]
```

TCP `127.0.0.1:7799`，**一行命令一行 JSON**：

| 命令 | 作用 |
| --- | --- |
| `status` | 队列数、状态栏文字、面板宽度、是否收起、并行数、窗口尺寸、**是否在录** |
| `rows` | 每一行：序号 / 文件名 / 状态 / 时长 / 体积 / 明细 / 是否本批 |
| `bgstate` | 背景图层的实际状态（图片、不透明度、放置方式、范围） |
| `addrows:N` / `clear` | 造 N 行假数据（覆盖 6 种状态）/ 清空 |
| `loglines[:N]` / `log[:N]` | 终端面板里显示的行 / 日志文件末尾 N 行 |
| `text:<id>` / `find:<id>` | 读某个控件（按 AutomationId）/ 找它是否存在 |
| `press:<id>` / `set:<id>=<值>` | 点它（按钮、勾选框）/ 给它设值 |
| `selcount` | 蓝色选中了几行、当前"同时录制数量" |
| `select:<行号>` / `selectrange:<a>-<b>` / `clearselect` | 按**界面显示的行号（1 起）**选中 / 清空选中 |
| `enabled:<id>` | 某个控件是否可用（比如空队列时"停止"该是灰的） |
| `sysmute` / `sysmute:on\|off` | 读 / 改系统端点静音 |

⚠ **两个坑**：
1. **模态对话框弹着的时候，读取类命令会卡住**（它们走 `Dispatcher.Invoke`，而模态框占着 UI 线程）。
   典型场景：一次拖进好几个"已经录过"的 rep → 程序弹询问框 → 这期间的 `status`/`rows` 全都不返回。
   要先想办法把那个框答掉（脚本里是给 `#32770` 发 `WM_COMMAND/IDNO`）。
2. `press:`/`set:` 碰勾选框时会**连 Click 事件一起补上** —— 本程序的勾选框都是挂在 `Click` 上
   （保存设置、改 ini），只改 `IsChecked` 的话值翻了、设置却没落盘。

## 验收脚本

`验证WPF-00` ~ `验证WPF-13`，全部纯 ASCII、可重复跑：

| 脚本 | 管什么 |
| --- | --- |
| 00 | 编译 + 能启动 |
| 01 | 界面壳、DPI、缩放、最大化不盖任务栏 |
| 02 | 调试接口 + 设置文件兼容 |
| 03 | 左栏控制面板（五张卡、收起/展开、宽度记忆） |
| 04 | 队列列表（增删、状态、滚动、框选） |
| 05 | 终端面板、折叠 |
| 06 | 录制流程接线（加 rep 进队列、清空） |
| 07 | 背景设置窗（实时预览、取消还原、确定落盘） |
| 08 | **默认界面切换**：不带参数 = 新界面，`--old` = 旧界面，`--wpf` 仍认 |
| 10 | 队列选中 →「同时录制数量」跟随、清空选择后不回退、空队列时按钮状态 |
| 11 | 已经录过的 rep → 弹询问 → 选"否"后标成已录制并跳过 |
| 12 | `Ctrl+B` 收起/展开面板、状态跨重启保持 |
| 13 | 「刷新」按钮重新检测已有视频、系统静音读写 |

跑法：**`powershell -File 验证WPF-0X-xxx.ps1`**（`00`~`13` 逐个）。
```powershell
# 千万别用管道接（`| grep ...`）：脚本启动的 GUI 子进程会继承管道的 stdout 句柄，
# 脚本跑完了管道还在等 EOF —— 看着像脚本卡死。要留证据就重定向到文件：
powershell -File 验证WPF-04-队列列表.ps1 > out.txt 2>&1
```
⚠ **脚本一律写成纯 ASCII**（注释、字符串、截图文件名都是）。PowerShell 5.1 读无 BOM 的 UTF-8
会当成 ANSI，中文字面量被搅坏之后报的错会完全跑偏；写错了还会直接语法错误。

⚠ **别让两套验收脚本同时跑**：每个脚本开头都会
`Get-Process RepRecorderWPF | Kill`，并行跑会互相把对方的实例杀掉，
结果看起来像功能坏了。

## 同步脚本为什么是 GBK 编码

`.bat` 里 `chcp 65001` + 大 UTF-8 文件会让 cmd **按字节偏移错位解析**
（表现是半个单词被当成命令：`'b%c'`、`'pe'`、`'ause'`）。中文 Windows 上写成 GBK、不写 `chcp` 就正常。
另外里面取时间戳用的是 `powershell ... Get-Date -Format`，**不是 `%date%`** ——
中文系统的 `%date%` 是"周六 2026/10/03"，会把 `for /f` 整行带崩。
