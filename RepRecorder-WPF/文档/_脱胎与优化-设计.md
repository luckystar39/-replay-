> 这是**设计**，不是实现步骤。实现步骤见 `_脱胎与优化-实现计划.md`，进度记在 `_脱胎与优化-台账.md`。
> 定稿日期 2026-10-12。起因：用户要求「WPF 版完全脱离 WinForms 独立」，同时把当日代码审查出的
> 修复项全部实施。

## 1. 目标与边界

**主目标**：WPF 版在**编译期和运行期**都不再依赖 `System.Windows.Forms`。

**并行目标**：实施 2026-10-12 审查出的全部修复项（批 B）与三件代码之外的事（批 C）。

**硬约束**

- `RepRecorder-旧版WinForms\`（旧版本体 exe + `源码\RepRecorder.cs` + 备份）**一个字不动**。
  用户明确要留着留念；本次剥离不动它，是因为它已经是一份完整独立的快照。
- 不改任何用户可见的功能、外观、默认设置。这一轮不应该让用户"发现哪里变了"，
  除了批 B 里那几条**修好了的毛病**。
- 全程不碰 git（用户自己管版本）。

**明确不做**（见第 8 节）

- 不换 `System.Drawing`（它是 GDI+ 图像处理，不是 WinForms）
- 不拆 `Core.cs`（剥离后约 3100 行）
- 不动更新通道 / 分发机制 / 版本号

## 4. 批 A：剥离 WinForms

### 4.1 删除边界

**删**

- `MainForm` 类（`Core.cs:1687-8460`）
- 11 个旧界面控件类（`Core.cs:8935-9816`）：`Bg` `HudCapButton` `BgPanel` `BgFlowPanel`

- `Program.Main` 里的 `Application.EnableVisualStyles()` /
  `Application.SetCompatibleTextRenderingDefault(false)` 与 `--old` 分支
- `using System.Windows.Forms;`：`Core.cs:19`、`Recorder.cs:23`
- `编译.bat` 里的 `/r:System.Windows.Forms.dll`
- `启动旧界面-退路.bat`（用户 2026-10-12 决定：删）
- 验证脚本 `验证WPF-08-默认界面切换.ps1` 退役（它整个就是测 `--old` 的）

**删不掉但会被牵连**：`Recorder.cs:4025-4247` 那 7 个 CLI 方法（`StopRecordingCli` 等）。
已 diff 确认它们与 `Program` 里的同名方法**逐字相同**，是同一次搬迁复制出来的重复。
保留 `Program` 那份（那是活的调用路径），删 `Recorder` 这份。

### 4.2 新文件 `src\Palette.cs`

把 `MainForm` 里的 **19 个** `Hud*` 静态颜色常量原值搬到中立的 `Palette` 类，值一个不改
（`HudBg` … `HudOrange`，定义见 `Core.cs:2880-2899`）。

- 命名空间 `RepRecorder`，`internal static class Palette`
- 字段类型仍是 `System.Drawing.Color`，**不用**改成 WPF 的 `System.Windows.Media.Color` ——
  WPF 侧本来就是 `Br(MainForm.HudX)` 这条路（`Ui.Br` 负责转 Brush），改成 WPF 颜色
  会牵动 96 处调用点的类型，纯属给自己找事。
- 机械替换 102 处 `MainForm.Hud` → `Palette.Hud`（含注释里的提及，一并改）。
- `Recorder.cs:186-193` 那 8 个转发属性（`static Color HudOff { get { return MainForm.HudOff; } }`）
  一并改成转发 `Palette`，保留名字，逻辑那边一行不用动。

### 4.3 对话框替换（`UiDialogs.cs` 4 处）

| 现在 | 换成 |
|---|---|
| `System.Windows.Forms.FolderBrowserDialog`（447、703） | 新文件 `src\FolderPicker.cs`，包 Win32 `IFileOpenDialog` + `FOS_PICKFOLDERS` |
| `System.Windows.Forms.OpenFileDialog`（710、926） | `Microsoft.Win32.OpenFileDialog`（WPF 自带，`PresentationFramework` 里就有） |

`FolderPicker` 要点：

- COM 接口 `IFileOpenDialog` / `IFileDialog` / `IShellItem`（`[ComImport]` + 手写 GUID 与方法序号）
- 选项 `FOS_PICKFOLDERS | FOS_FORCEFILESYSTEM | FOS_PATHMUSTEXIST`
- 初始目录：`SetFolder(SHCreateItemFromParsingName(...))`，失败则忽略（不因为初始目录无效就弹不出来）
- 结果：`GetResult` → `GetDisplayName(SIGDN_FILESYSPATH)` → 路径字符串；用户取消 → 返回 `null`
- 任何异常都吞掉并返回 `null`，调用方维持"取消"的语义（现在的代码就是这么用的）

顺带把那个 Windows XP 风格的老树形对话框换成现代选择器 —— 这是这次唯一一处
**用户能看见的变化**，且是变好。

**没有自动化覆盖**：现有 18 个脚本里没有一个驱动过这两个对话框（改之前也没有），
所以这块靠人工点一次验收。

## 7. 验证与回滚

**验证节奏**

- 批 A 是删除性操作：先定位起止锚点、确认字节数，改完**立刻编译**，编译一过立刻跑全量
- 批 B 每项改完先跑相关脚本，一批做完再跑全量
- 全量 = `测试\_runall.sh`（退役 08、新增 19 之后共 18 个脚本，其中 `验证WPF-18` 约 700 秒，
  整体 15~20 分钟）
- 每条结论都要有命令 + 实际输出，落到台账

**删除的安全性（R21 的教训）**

上一轮用 `str.index` + 切片做跨区剪切，范围算错静默删掉了 `Ui.cs` 约 1770 行，且当时没有副本。
这次的做法：

1. 删除范围按**锚点行内容**定位（`    public class MainForm : Form` 到 `    public static class Program`），
   不按行号硬编码
2. 删之前断言起止锚点唯一、且被删区间字节数在预期量级（约 6774 行 / 约 880 行）
3. 删之前把 `Core.cs` 复制一份到**仓库外**的临时目录（不往仓库里加备份文件）
4. 删完立刻 `编译.bat`；编译不过就从临时副本还原，不去猜
5. 全程改完跑全量

## 8. 明确不做

- **不换 `System.Drawing`**：它用于截图、黑帧检测、`lastframe.jpg`，是 GDI+ 图像处理而非 WinForms。
  换成 WPF `BitmapSource` 要重写整条图像路径，风险与收益完全不成比例。
- **不拆 `Core.cs`**：剥离后约 3100 行、10 个类型，仍然可读。这一轮的风险已经集中在"删 7600 行"上，
  再叠加搬文件会让"编译失败时到底是删错了还是搬错了"变得无法区分。想拆可以之后单独一轮。
- **不删 `RepRecorder-旧版WinForms\` 里任何东西**（含 `源码\`、`备份\`、`_恢复\`、`_重复副本\`）。
- **不动更新通道**（`Update.cs` / `发版-生成.ps1` 的传包逻辑 / `version.json`）。
- **不改 `文档\说明.md` 之外**的用户文档措辞（除 C1 的版本号）。
